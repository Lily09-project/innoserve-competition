# 決賽展示與答詢

## 展示主線

先說明作品處理的問題：告警需要判定依據、證據核對與可追溯的後續處理。以架構圖說明雙分支17類判定、529維任務檢索、本機AI稽核及策略閘門；接著播放方法動畫，再用成果網站檢視相同測試集比較、17類結果及六種隔離情境。

完整本機展示從預載模型開始，選擇真實輸入重跑，依序核對正式分類、Top-5證據、同事件AI回覆、策略檢核與回條。部署使用同次執行結果；六種隔離情境已有保存結果可作現場備援。方法影片中的設備、封包及PDU視窗是流程視覺化，模型實測使用真實預處理張量。

## 三項技術創新

1. CTBM從內容、時間差與方向判定，PBCNN補充短窗位元組模式，由凍結OOF Gate融合成17類正式機率。
2. 512維表徵與17維機率組成529維任務向量，從訓練案例庫查詢Top-5，讓分類依據有案例可核對。
3. AI依證據輸出支持、複核或不確定，不改寫分類；策略閘門再檢查白名單、信心、共識、範圍與有效期，將事件及執行批次綁定至處置回條。

- 檢索：1,550筆訓練案例、463筆查詢，Top-5 97.62%、MRR@5 93.89%。依每類配額取樣，train/test事件識別碼重疊0筆。

- 整合：17類真實張量重跑，17次本機AI呼叫；6種事件接續隔離網路，4種實際套規則、2種維持監測或蒐證。背景服務與回復完整性各6/6通過。
- 網路範圍：隔離TCP交易與規則驗證，無原始攻擊重播防禦率宣稱。公開網站為保存結果展示，GPU模型及網路執行由本機版提供。

## 評審可能提問

**前後段如何確實對齊？** 正式17類標籤順序、模型來源、529維表示版本及train-only案例庫均有固定合約。事件識別碼與執行識別碼沿偵測、檢索、稽核與處置傳遞，回條綁定原事件；過期執行請求會遭拒。

**RAG是否直接修復所有攻擊？** 檢索與AI負責形成證據與稽核判斷，受控動作由策略閘門及已定義劇本執行。現有驗證呈現登入服務保護、流量限制、目的端連線限制、監測與蒐證；各類策略路徑見FRAMEWORK.md。

**為什麼稽核會有支持、複核與不確定？** AI依證據給出分流，避免缺乏支持的判定直接進入可干預動作。現有463筆結果保留全部分流與誤判統計，策略另加門檻。

**如何保護正常服務？** 策略在隔離網路驗證，量測目標與背景交易，讀回規則並驗證到期回復；六種情境的背景服務均通過。

**17類是否等於17種攻擊都能自動修復？** 17類是偵測輸出，含正常流量。各類有明確策略路徑，已驗證隔離流量設定與未干預的蒐證路徑分開；不將類別數當作部署劇本數。
