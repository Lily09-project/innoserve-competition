# 決賽六題答詢口徑

評審答詢偏向細節與實際應用，六題依此設計。先用第一句回答，再沿備詢頁的圖說明，最後指出證據；主動回答控制在約半分鐘，細節依追問展開。以下秒數不是實際朗讀量測。

## Q1｜一筆告警多久能產生處置？能即時嗎？｜第10頁上半

第一句：暖機後單筆中位數約0.95秒，其中本機AI稽核約0.91秒是主要耗時。

指圖：偵測34.17毫秒、檢索1.52毫秒、本機AI 914.40毫秒，三條長條同一比例尺。這是RTX 4090上17次單筆整合驗證的中位數，不是負載測試；沒有量測冷啟動、p95或吞吐量，不回答「每秒可處理幾筆」。

可查證：[實測與證據索引](實測與證據索引.md#暖機後樣本延遲)、[實測索引](../deliverables/source/release-validation.json)。

## Q2｜哪一類最容易判錯？判錯怎麼辦？｜第10頁下半

第一句：最弱的是Web-XSS，F1 42.73%，最常被判成Web-BruteForce。

指圖：Web-XSS測試120筆有71筆判成Web-BruteForce，Web-BruteForce F1 75.15%次低，兩類流量形態接近。判錯時，AI若回複核或不確定，或信心未達0.8、Top-5同類不足4筆，策略都不放行，保留人工複核。

可查證：[偵測結果](../results/detection_17class.json)、[策略風險分析](../results/policy_risk_analysis.json)、[策略檢查](../app/pipeline.py)。

## Q3｜處置會不會影響正常使用者？規則會一直留著嗎？｜第11頁上半

第一句：策略只限指定來源、服務與期限，到期自動撤銷；隔離實測背景服務保留6/6。

指圖：四道限制為正常類禁止破壞性處置、動作需符合類別白名單、只限指定來源與服務、期限30至900秒。隔離實測設定30秒，約30.1秒撤銷，回復完整6/6。範圍是六種隔離TCP情境，不等同真實攻擊防禦率。

可查證：[六情境逐項結果](../results/framework_validation.json)、[回復驗證](../deliverables/source/recovery-validation.json)。

## Q4｜本機AI會不會亂判？判錯怎麼辦？｜第11頁下半

第一句：AI只能回三態結論，不能改寫正式分類；463筆格式全部有效，改動分類0筆。

指圖：支持精確率97.11%；AI輸入不含真實標籤。12筆錯誤支持中，6筆仍只蒐證或被策略擋下；其他處置同樣要通過信心、證據與期限檢查。不回答成「AI不會出錯」。

可查證：[正式稽核結果](../results/local_judge_17class.json)、[策略風險分析](../results/policy_risk_analysis.json)。

## Q5｜遇到沒看過的新攻擊怎麼辦？案例庫怎麼更新？｜第12頁上半

第一句：本次沒有量測未知攻擊；機制上證據不足就保留蒐證、交給人工，不自動處置。

指圖：偵測模型固定輸出17類；Top-5同類不足或AI不確定時走人工確認。確認後的案例可加入案例庫，不需改AI提示；新增類別則需重新訓練偵測模型。不宣稱能自動辨識全新攻擊。

可查證：[檢索結果](../results/retrieval_17class.json)、[策略檢查](../app/pipeline.py)。

## Q6｜實際導入需要什麼？資料會外流嗎？｜第12頁下半

第一句：一台本機GPU工作站即可執行偵測、案例檢索與本機AI，外部API呼叫0次。

指圖：工作站為RTX 4090、本機Llama 3 8B與案例庫，私有權重、輸入與逐筆回覆不外傳。接新來源需轉成相同欄位與表徵格式；處置輸出為路由器規則，目前以Mininet隔離驗證，尚未接入企業正式網路。

可查證：[工作站設定](../README.md#完整本機模型與隔離驗證)、[稽核彙整](../results/local_judge_17class.json)、[預檢入口](../scripts/preflight.py)。

## 追問的回答原則

被問到未列出的比較或能力時，直接界定本次正式結果所支持的範圍，再指出可核對的產物。對新來源、任意PCAP、併發容量或真實場域攻擊，不用既有17筆展示或6種隔離情境代替量測。完整私有研究紀錄由團隊保留，不在匿名投影中開啟個人路徑或GitHub帳號。
