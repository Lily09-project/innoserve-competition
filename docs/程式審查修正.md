# 程式審查修正與驗收

日期：2026-10-29。本輪修正五項審查發現，涵蓋證據選取、版本追蹤、AI稽核、隔離處置及私有資產匯入。原有模型權重、分類門檻、案例庫與封存成效數據維持原值；簡報、海報、影片及離線包維持原檔。

## 修正內容

| 審查問題 | 修正後行為 | 回歸檢查 |
| --- | --- | --- |
| 通過摘要可掩蓋損壞逐筆回條 | 重新驗證17筆事件四階段紀錄、判定、證據、Judge、策略及6筆同次執行回條；摘要與逐筆統計必須一致 | 破壞事件鏈、跨批次回條、重新雜湊的失敗處置均遭拒 |
| 程式指紋漏列實際執行來源與模型資產 | 追蹤23個執行來源檔；另追蹤23個權重、Gate、模型來源、tokenizer及輸入資產，連同執行設定產生資產版本 | 每個來源與資產單獨變更均使版本改變；API、預檢與發布稽核必須符合相同版本 |
| 無效JSON或不完整Judge上下文仍可能允許處置 | 明確檢查JSON有效性、完整輸入、固定提示詞與模型版本；新版紀錄另綁定完整上下文雜湊 | 無效support、缺payload、提示詞或模型版本不符、上下文遭改均遭拒；解析失敗只走不確定蒐證 |
| 零規則與未產生影響仍可被列為處置成功 | 依實際策略驗證規則數、來源與服務範圍、DROP讀回、交易影響、背景服務及實際TTL回復 | 讀回空白、錯誤port、未產生預期影響、提前回復與背景中斷均遭拒；監測／蒐證保留零規則 |
| 任意JSON／NPZ可被發布為正式私有資產 | 暫存區先檢查案例庫hash、17類標籤、唯一ID與配對、train/test分離、實際Top-5及Judge輸入、17類張量形狀與有限值，再發布 | 垃圾JSON／NPZ、錯誤hash、缺張量及重複ID均遭拒；失敗不留下可用目標 |

新產生的Judge紀錄使用第二版上下文綁定；既有紀錄以完整payload、有效性及相同提示詞檢查保留相容性。檔案雜湊與事件鏈用來檢查一致性，不宣稱具有數位簽章或防止具寫入權限者偽造的能力。

## 驗證範圍

104項Python測試涵蓋既有合約與本輪新增15項測試；合成fixture只供驗證程式拒絕錯誤的行為，不列入模型成效。公開結果的零規則偽成功情境另有專用回歸測試。

真實驗證使用既有1,550筆訓練案例、463筆私有事件／Judge紀錄與17類展示張量。重新執行17類模型推論與17次本機AI，再依預定六類測試隔離TCP交易、規則讀回與30秒期限回復。公開彙整、樣本延遲與證據hash見[實測與證據索引](實測與證據索引.md)及[release-validation.json](../deliverables/source/release-validation.json)。

不同服務port的誤判案例不強迫宣稱有防禦效果；驗證依實際預測所產生的策略及實際評估服務判斷是否應影響交易。監測及蒐證情境要求交易維持成功，不能被混列為封鎖效果。

沒有重新訓練、原生攻擊重播、正式網路部署、漏洞修補率或負載壓力測試。原生播放依使用者要求排除；媒體僅做既有合約、SVG與實際影像編譯檢查。

## 重現指令

公開合約與媒體檢查依[驗收與重現方式](驗收與重現方式.md)執行。完整模型與隔離驗證在配置真實私有資產的工作站執行：

```bash
python scripts/preflight.py --warmup
python scripts/audit_final_chain.py
python scripts/audit_alignment_assets.py --audit-dir PATH_TO_SUCCESSFUL_AUDIT
python scripts/export_framework_validation.py --audit-dir PATH_TO_SUCCESSFUL_AUDIT
python scripts/release_inventory.py --audit-dir PATH_TO_SUCCESSFUL_AUDIT
```

匯出與發布索引會比對當下模型資產版本；舊證據不能直接套用新程式或不同權重。最後更新交付manifest，再執行全部測試、公開檔案與文件檢查，並在沒有私有資產的乾淨clone驗證。
