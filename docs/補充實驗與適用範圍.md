# 補充實驗與適用範圍

本輪補上稽核對照、檢索敏感度、真實SSH服務及重複整合效能。偵測權重、Gate、測試切分與正式提示詞保持原版；補充AI實驗另採預先固定的共同提示詞。數值來自實際執行，不將個別模組的結果當成整套系統的實網防禦率。

## 一、相同查詢的五組稽核對照

固定463筆偵測輸入、1,550筆訓練案例、同一Llama 3 8B權重與確定性解碼設定。三個AI組各產生463筆新回覆，共1,389次。輸入不含真實標籤或事件識別碼；標籤只在評估時計算精確率。共同提示詞容許有／無案例兩種輸入，與既有正式提示詞不同，不能直接把差異歸因於模型升級。

| 稽核輸入／方法 | 支持數 | 支持精確率 | 支持覆蓋率 | 錯誤支持數 |
| --- | ---: | ---: | ---: | ---: |
| 信心與分支一致規則 | 377 | 97.61% | 81.43% | 9 |
| 529維案例一致規則 | 400 | 98.50% | 86.39% | 6 |
| AI，無案例輸入 | 419 | 97.14% | 90.50% | 12 |
| AI，512維檢索案例 | 436 | 95.64% | 94.17% | 19 |
| AI，529維檢索案例 | 436 | 95.64% | 94.17% | 19 |

支持精確率須與覆蓋率一起看。本次AI檢索組支持更多事件，也支持更多錯誤分類；沒有證據顯示其優於規則組。512維與529維的支持數與精確率相同，複核／不確定的分配略有不同。所有組最後使用同一正式529維證據及Guard，因此比較的是稽核輸入，而非整套系統完全移除檢索。五組經共同Guard仍各允許6筆錯誤分類的介入授權，全部只計算策略，沒有執行網路動作；正式分類改寫數為0。

資料：[五組完整彙整](../results/auditor_ablation.json)。既有正式提示詞的415支持、97.11%支持精確率仍屬原實驗，不能用本輪不同提示詞的結果替換或宣稱改善。

## 二、訓練案例庫縮減敏感度

固定463筆查詢與模型，在既有訓練案例庫內分層無放回抽樣，比例50%、75%、100%，種子42–46。每類至少保留5筆，未新增或重選查詢，也沒有重新呼叫AI。512維與529維各15組，共30組。

| 案例庫比例 | 五種子Top-5命中率範圍 | 解讀 |
| --- | --- | --- |
| 50% | 96.98%–98.27% | 兩種向量的命中率相同 |
| 75% | 97.19%–97.84% | 兩種向量的命中率相同，部分MRR不同 |
| 100% | 97.62% | 完整案例庫；五個種子對應同一批案例 |

不同抽樣不保證案例越多命中率越高。本次只能描述既有案例庫縮減的敏感度，不能推論新來源、跨資料集或新查詢的泛化能力，也未證明529維優於512維。真實標籤只用於計分，檢索不讀取它。

資料：[30組逐項結果](../results/retrieval_sensitivity.json)。

## 三、真實SSH服務、正常流量與期限回復

在Mininet隔離命名空間啟動Paramiko SSH服務，執行加密握手、密碼認證及固定健康回應。使用臨時實驗帳號設定與主機金鑰，不修改作業系統帳號；客戶端核對固定主機金鑰。三輪各從受限來源及其他來源測試同一個22埠，每波8個並行連線。

處置採既有真實CIC SSH事件的完整判定與稽核鏈，驗證後套用原有來源限速規則；實驗生成的SSH連線用來測試規則效果，沒有宣稱已被偵測模型即時辨識。

| 測試項目 | 套用前合計 | 套用後合計 |
| --- | ---: | ---: |
| 錯誤密碼到達認證並被拒絕 | 24/24 | 6/24 |
| 相同受限來源的合法登入與健康回應 | 24/24 | 6/24 |
| 其他來源的合法登入與健康回應，同22埠 | 24/24 | 24/24 |

錯誤密碼原本就不能登入；6/24代表仍到達認證階段的嘗試，不是成功入侵數。來源限速沒有辨識單一來源中誰是合法使用者，因此同來源合法登入也受限，不能宣稱零副作用。規則期限30秒，三輪皆實際等待後移除；兩來源各恢復24/24健康回應，規則讀回皆為空，網路、程序與連線資源清理通過。

此PoC補足真實服務協定與同埠正常流量證據，範圍仍為隔離SSH來源限速，不代表實體設備部署、漏洞修補、其他攻擊類型或生產網路防禦率。

資料：[三輪服務與回復結果](../results/ssh_service_poc.json)。

## 四、獨立程序載入與暖機效能

同一RTX 4090工作站執行三個獨立Python程序，各重新載入權重並執行首次推論，再對17個真實預處理輸入循環102次，共306次暖機整合呼叫。重複輸入是延遲樣本，不是新增準確率樣本；各次含偵測、檢索、AI稽核、Guard與結果寫檔，未包含HTTP排程及網路處置。作業系統檔案快取未清除，所以稱為程序冷啟動，不是斷電冷啟動。

| 指標 | 實測值 |
| --- | --- |
| 三程序模型載入範圍 | 20.91–21.18 秒 |
| 三程序首次推論範圍 | 1.61–1.71 秒 |
| 306次暖機整合p50／p95 | 457.78／687.57 ms |
| 序列處理速率 | 2.10 次／秒 |
| 與保存正式分類不一致數 | 0／306 |

實際載入時間、首次推論、暖機p50／p95及PyTorch配置顯存峰值以[效能彙整](../results/pipeline_latency.json)為準；序列每秒呼叫量只描述本機逐筆處理，不代表多使用者併發容量。原17次類別覆蓋驗證仍保留於[原實測索引](實測與證據索引.md)。
